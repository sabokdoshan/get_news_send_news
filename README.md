# صبا رسانه — ربات خبری تأمین اجتماعی (کاملاً رایگان)

فایل‌های تحویل داده شده:

| فایل | کاربرد |
|---|---|
| `social_security_news_bot.py` | اسکریپت پایتون مستقل — قلب ربات |
| `news-bot.yml` | ورک‌فلوی **GitHub Actions** (پیشنهاد اصلی — مطابق روش قبلی شما) |
| `apps_script_trigger.gs` | تریگر اختیاری از **Google Apps Script** برای اجرای دقیق هر ۳۰ دقیقه |
| `saba_media_news_workflow.json` | جایگزین: ورک‌فلوی **n8n** (اگر بعداً خواستید امتحان کنید) |
| این فایل | راهنمای راه‌اندازی |

## روش پیشنهادی: GitHub Actions (+ اختیاری Apps Script)

1. یک مخزن (repository) گیت‌هاب بسازید و `social_security_news_bot.py` را در ریشه‌ی آن قرار دهید.
2. پوشه‌ی `.github/workflows/` بسازید و `news-bot.yml` را داخل آن کپی کنید.
3. در تنظیمات مخزن: **Settings → Secrets and variables → Actions** این مقادیر را اضافه کنید:
   - `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` (برای ارسال خودکار به تلگرام)
   - `GROQ_API_KEY` (اختیاری، برای خلاصه‌سازی با کیفیت بالاتر)
4. در **Settings → Actions → General → Workflow permissions** گزینه‌ی
   "Read and write permissions" را فعال کنید (لازم است تا فایل `seen_links.json`
   بعد از هر اجرا commit شود و خبر تکراری ارسال نشود).
5. همین‌جا کار تمام است — خودِ گیت‌هاب هر ۳۰ دقیقه اجرا می‌کند (تب Actions
   را برای دیدن اجراها ببینید).

اگر می‌خواهید دقیقاً مثل روش قبلی‌تان، زمان‌بندی از بیرون و با دقت بیشتر
کنترل شود:
6. `apps_script_trigger.gs` را در یک پروژه‌ی جدید در script.google.com بریزید.
7. یک GitHub Personal Access Token با دسترسی `workflow`/`Actions: write` بسازید
   و در Script Properties با نام `GITHUB_TOKEN` ذخیره کنید.
8. مقادیر `OWNER` و `REPO` را در بالای اسکریپت جایگزین کنید.
9. یک Time-driven trigger برای تابع `triggerGithubWorkflow` بسازید: هر ۳۰ دقیقه.
   از این پس Apps Script دقیقاً سروقت، Action گیت‌هاب را صدا می‌زند
   (فیلد `schedule` در yml را هم می‌توانید نگه دارید، ضرری ندارد).

منبع خبر در هر دو: **Google News RSS** (رایگان، بدون کلید API) با فیلتر روی
کلمات کلیدی تأمین اجتماعی/بازنشستگان/شستا و... . خلاصه‌سازی به‌صورت پیش‌فرض
با یک الگوریتم ساده‌ی استخراجی است؛ اگر خواستید خلاصه‌ها با کیفیت مدل زبانی
باشد، یک کلید رایگان از **console.groq.com** بگیرید (پلن رایگان دارد) و آن
را در جای مشخص‌شده قرار دهید.

## روش‌های جایگزین

### اجرا با Python + cron روی سرور شخصی

```bash
pip install --user requests   # فقط کتابخانه‌های استاندارد استفاده شده، این مرحله اختیاری است
crontab -e
```
این خط را اضافه کنید (هر ۳۰ دقیقه اجرا می‌شود):
```
*/30 * * * * /usr/bin/python3 /path/to/social_security_news_bot.py >> /path/to/log.txt 2>&1
```
متغیرهای محیطی اختیاری قبل از اجرا:
```bash
export GROQ_API_KEY="..."        # اختیاری، برای خلاصه‌سازی با کیفیت بالاتر
export TELEGRAM_BOT_TOKEN="..."  # اختیاری، از @BotFather رایگان بگیرید
export TELEGRAM_CHAT_ID="..."    # آیدی عددی گروه/کانال مقصد
```
اگر این دو متغیر تلگرام تنظیم نشوند، اسکریپت فقط خروجی JSON را در ترمینال/لاگ چاپ می‌کند.

### اجرا با n8n (بدون نوشتن کد، اگر بعداً خواستید امتحان کنید)

1. یک نمونه‌ی n8n رایگان بالا بیاورید (self-host با Docker، یا اکانت رایگان n8n Cloud).
2. از منوی Workflows روی **Import from File** بزنید و `saba_media_news_workflow.json` را انتخاب کنید.
3. روی نود **Config** کلیک کنید و مقدار `telegramChatId` (و در صورت تمایل `groqApiKey`) را وارد کنید.
4. روی نود **ارسال به تلگرام** کلیک کنید و Credential تلگرام (Bot Token از @BotFather) را متصل کنید.
5. ورک‌فلو را **Active** کنید — از این پس هر ۳۰ دقیقه خودکار اجرا می‌شود.

## نکته‌ی مهم درباره‌ی فیلترینگ اینترنت در ایران

- `news.google.com`، `api.groq.com` و `api.telegram.org` معمولاً از **داخل ایران**
  با محدودیت یا فیلترینگ مواجه می‌شوند.
- خوشبختانه با روش GitHub Actions این نگرانی خودبه‌خود حل می‌شود: اجراکننده‌های
  گیت‌هاب (GitHub-hosted runners) روی سرورهای خارج از ایران اجرا می‌شوند، پس
  به فیلترشکن نیازی نیست. Apps Script هم روی سرورهای گوگل اجرا می‌شود، نه
  روی کامپیوتر شما — آن هم مشکلی با فیلترینگ ندارد.
- تنها جایی که فیلترینگ می‌تواند اثر بگذارد، لحظه‌ی دیدن نتیجه در تلگرام از
  داخل ایران است که به فیلترشکن معمول تلگرام (نه سرور) مربوط می‌شود.

## محدودیت‌های شناخته‌شده

- Google News RSS برای هر خبر فقط چکیده‌ی کوتاه می‌دهد، نه متن کامل؛ به همین
  دلیل خلاصه‌ی ۸۰-۱۲۰ کلمه‌ای بدون کلید Groq ممکن است کوتاه‌تر یا کلی‌تر باشد.
- تشخیص دقیق «۳۰ دقیقه‌ی اخیر» به pubDate فید بستگی دارد؛ اسکریپت به‌جای آن
  بر اساس **لینک خبر** جلوگیری از تکرار می‌کند (هر لینک فقط یک‌بار ارسال می‌شود)
  که در عمل معادل «فقط اخبار جدید» است.
